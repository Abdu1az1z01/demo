# Как выложить Zetta Billing в интернет

После этого сайт будет открываться по адресу вида `https://zetta-billing.onrender.com`
с любого компьютера и телефона, и все сотрудники будут работать с одной общей базой.

Используем два бесплатных сервиса:

| Что | Где | Зачем |
|---|---|---|
| Сайт + бэкенд | [Render](https://render.com) | запускает программу по `Dockerfile` из этого репозитория |
| База PostgreSQL | [Neon](https://neon.tech) | хранит абонентов, начисления, сотрудников (бесплатно, без срока) |

## 0. Перед началом

Всё должно быть слито в ветку `main` репозитория `demo`: сайт (React, папка `frontend`),
бэкенд, `Dockerfile`, `render.yaml`, профиль `prod`.

## 1. База данных в Neon

1. Зайдите на https://neon.tech → **Sign up** → войдите через GitHub.
2. **Create project**: имя `zetta-billing`, регион **Europe (Frankfurt)**, Postgres любой версии.
3. На странице проекта нажмите **Connect** и скопируйте **Connection string** —
   строку вида `postgresql://neondb_owner:пароль@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   Это ваш `DATABASE_URL`. Никому его не показывайте.

## 2. Сервер в Render

1. Зайдите на https://render.com → **Get Started** → войдите через GitHub.
   Разрешите Render доступ к репозиторию **demo** (он приватный).
2. **New** → **Blueprint** → выберите репозиторий **demo** → Render прочитает `render.yaml`.
3. Render попросит заполнить:
   - `DATABASE_URL` — строка из Neon (шаг 1.3);
   - `ZETTA_DIRECTOR_PASSWORD` — придумайте надёжный пароль директора (логин: `director`).
4. Нажмите **Apply**. Первая сборка идёт 5–10 минут (вкладка **Logs**).
   Когда в журнале появится `Zetta Billing запущен`, сайт готов.
5. Адрес сайта — вверху страницы сервиса, например `https://zetta-billing.onrender.com`.

## 3. Первый вход

1. Откройте адрес сайта → логин `director`, пароль из `ZETTA_DIRECTOR_PASSWORD`.
2. **👥 Сотрудники** → **+ Добавить сотрудника** — заведите инспекторов, выдайте им логины.
3. **💰 Тарифы** — проверьте или установите тарифы.

В `render.yaml` включены тестовые данные (`ZETTA_DEMO_DATA=true`): 100 тестовых абонентов,
тарифы и инспектор `inspector` / `inspector123`. Для настоящей работы до первого запуска
поставьте в Render `ZETTA_DEMO_DATA=false` (Environment) — тогда база будет пустой.
Если тестовые данные уже созданы, а нужно начать с чистой базы — создайте в Neon новую базу
(или новый проект) и поменяйте `DATABASE_URL`.

## Обновления

- Изменения в ветке `main` репозитория `demo` (и сайт в папке `frontend`, и бэкенд)
  Render выкладывает сам.

## Что нужно знать о бесплатном тарифе Render

- Если сайтом никто не пользуется 15 минут, сервер «засыпает». Первое открытие после этого
  занимает около минуты — потом работает быстро. Платный тариф (от $7/мес) не засыпает.
- При перезапуске сервера все сотрудники выходят из системы и входят заново
  (данные в базе при этом не теряются).

## Переменные окружения (для любого хостинга с Docker)

| Переменная | Обязательно | Что это |
|---|---|---|
| `DATABASE_URL` | да | `postgresql://логин:пароль@хост/база?sslmode=require` или `jdbc:postgresql://хост:5432/база` |
| `DATABASE_USERNAME`, `DATABASE_PASSWORD` | нет | нужны только если `DATABASE_URL` в формате `jdbc:` без логина |
| `ZETTA_DIRECTOR_PASSWORD` | да | пароль директора; без него сервер не запустится |
| `ZETTA_DIRECTOR_LOGIN` | нет | логин директора, по умолчанию `director` |
| `ZETTA_DEMO_DATA` | нет | `true` — создать тестовые данные, по умолчанию `false` |
| `PORT` | нет | порт; хостинг задаёт сам, по умолчанию `8080` |

## Без интернета: работа в одной локальной сети

Если все сотрудники в одном офисе (одна сеть Wi-Fi), можно обойтись без хостинга:
запустите ZettaBilling.exe на одном компьютере, узнайте его адрес (`ipconfig` → IPv4, например
`192.168.1.25`) и откройте на других компьютерах `http://192.168.1.25:8080`.
При первом запуске Windows спросит про брандмауэр — разрешите доступ для частных сетей.
